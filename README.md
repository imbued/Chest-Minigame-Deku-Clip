# Chest-Minigame-Deku-Clip

- one big limitation of this script currently is that it fails for angles like 0x38ff where if you target and then untarget and then wait long enough, the camera angle will increment to 0x4000. this sort of camera behavior is properly accounted for for angle like 0xff90, though the behavior is a little different in the corresponding angle range (but was necessary to get working because we use this range for the actual deku spin clip and the deku spin is untargeted meaning the camera can update)
- to fix this limitation, I need to run a Lua script that checks all 4096 angle bins and presses target, then wait until maybe the camera angle goes e.g. 10 frames in a row without updating and report the final number as the camera angle.  It is important that you do NOT confuse this with `FacingAngleToTargetedCameraAngle` which specifically uses the camera angle while holding target, but there may be places you need to no longer use `FacingAngleToTargetedCameraAngle` to determine the final camera angle. You also need to update `test-cmg-solution.lua` with a corresponding lookup table so that when it performs the setup it'll actually wait for the camera to finish updating before doing something like a cardinal turn.

- adding a simple script to parse the solutions.txt and returning a list of all goal angles (will have to map the parsed targeted walking angles to their corresponding range of angle values) as well as the setup's final angle and camera angle. This is because a lot of setups will repeat this info, so might as well batch check if they have good angle setups before trying to look into them more.
